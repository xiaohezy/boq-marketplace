# 发布纪律与自动化验收

## 发布

1. **复用同一 appId 发布**——域名（<prefix>.app.workbuddy.host）和已分发链接才能保住；新 appId = 新域名 = 老链接全死。
2. **发布目录只放应用文件**：入口 index.html + .genie。用户真实业务文件（询价单/合同）绝不放入——整目录会上传。
3. 发布前四件套自检：① `node --check` 提取的 script 段（防 Edit 写入字面 `\"` 等语法伤）② 关键流本地预览模式过一遍 ③ i18n 新词条已补 ④ 数据库变更已先在服务端 migrate 完成。
4. 攒批发布：不影响数据记录的小修攒到一起发，没必要天天发（用户原话）。
5. 发布后冒烟：密码登录 → 角色正确 → 核心列表有数 → 一条关键链路点通。

## 自动化验收（外挂 platform-acceptance-browser 技能）

功能上线 ≠ 能用。每个角色每条链路用浏览器自动化真点一遍：

- **七条铁律**（agent-browser 本机坑全录）：直调 native exe、清代理 wrapper、单链条模式、CSS/eval 弃 @ref、confirm 预置、长任务 9s 短轮询、eval 可 await promise 直接查库核验。
- **OTP 文件握手**：真实邮箱注册链路全自动（浏览器点发送 → Agent Mail 收码 → 文件传递 → 回填）。
- **服务端核验**：UI 操作后必须 eval 查库确认落库（状态机/留痕/金额复算——实测定标总价 868.25 与手算分毫不差才算过）。
- 验收报告模板：通过项清单 + P1/P2/P3 分级问题 + 残留数据清单 + 下一步建议。

## 验收残留数据处理

- 测试账号/测试供应商/模拟报价：**默认保留**（演示样板），删除需用户拍板。
- 留痕日志不删（审计完整性），误写的留痕用一条对冲说明而不是删除。

## 版本与技能同步

- 每次验收发现的新坑 → 回写验收技能；每次解析/业务新教训 → 回写业务技能。**技能不维护就是负债。**
- 平台级用户约定（公司主体/关键客户/命名规范）写工作区 MEMORY.md，不写进通用技能。
