# 平台解析实战坑与工程对策（2026-09-18 → 2026-10-05 沉淀）

来源：外贸智能报价平台（trade-quote.app.workbuddy.host）真实运行 + 全链路自动化验收 + 存量数据修复。
与 validation-rules.md（22 条对账规则）互补：那是对**文件内容**的校验，这是对**解析工程链路**的兜底。

## 一、送模型之前（输入侧）

1. **宽表列截断（静默丢列，最阴险）**
   - 现象：>8 列的询价表（管道 11 列、风机 10 列）数量/单位列被裁掉，qty 全 null 或 AI 误拿风量当数量。
   - 对策：裁剪上限 `MAX_COLS=26` + `sheetWidth()` 按实际表宽自适应，禁止写死前 N 列。
   - 验收信号：解析后 **qty 全 null = 先怀疑列截断/表头错位，不要怀疑模型**。

2. **表头标签与列错位**
   - 现象：自制/转发表格表头写错一列，AI 把 Unit 列当 Qty（qty 全 null）。
   - 对策：造数/转发脚本里 `assert len(表头)==len(列)`；解析后自检 qty 缺失率 >30% 即报警。

3. **客户端预过滤再送模型**
   - 空行、表头行、SECTION 标题、无数量的全大写英文标题行，在客户端先剔除（isNoiseRow），
     别把噪声行算进"批次行数"浪费 token；>200 行分批解析后合并。
   - 送模型裁剪纪律：每批 ≤200 行、列宽自适应、单元格截 80 字。

## 二、模型侧

4. **多模型选型实测基准**
   - glm-5.3-flash：62 行解析 >150s 未完成（不可用）；deepseek-v4-flash：61 行 ~26s（可用基准）。
   - 下拉同名陷阱：hy3 / hy3-x、hy4-preview / hy4-preview-x 显示名相同——选择器必须按 **id** 去歧，按名字正则匹配会选错。

5. **json_object 偶发带 markdown 围栏**
   - 实测 1/160 概率输出 ` ```json {...} ``` ` 导致 JSON.parse 失败。
   - 对策：解析前剥围栏 + 取首个 `{` 到末个 `}` 子串；失败重试 1 次再放弃（批次级缓存防重复烧钱）。

6. **视觉通道解析扫描件/截图（替代传统 OCR）**
   - 多模态消息 `image_url: data:image/jpeg;base64,...` 直接结构化：63/63 单元全成功（45 张 WhatsApp 截图 + 18 份扫描 PDF）。
   - PDF 先 pymupdf 渲 150dpi JPEG 页图（≤6 页）；图片 ≤1MB 可直传。
   - brochure/产品图无价格时必须输出空 rows，禁止硬猜价格。

## 三、解析之后（存量治理）

7. **旧提示词存量脏数据 ≠ 代码 bug**
   - 判定顺序：先查当前提示词是否已含约束（description_cn 强制非空/列映射纪律/缩写词表），
     已含则问题是**存量数据**，走修复管线而不是改代码。

8. **存量修复管线（repair_items.js 模式，实测 235/235 成功）**
   - 分批送 LLM 修复（30 条/批，temp 0.1）→ **id 集合 + 条数双重校验**（防模型抖动增减行）→
     每批增量写缓存文件 → `--apply` 才逐条 UPDATE → task_logs 留痕「解析修复」。
   - 缓存复用：缓存条数与待修集合 id 完全一致则跳过 LLM（模型抖动失败后可零成本重跑）。
   - 循环陷阱：缓存判断必须整块包裹解析循环（`if (!repaired.length) { for ... }`），
     否则第一批后条件翻转提前退出（实测只写 30/235 条的事故）。

## 四、价格数据底座

9. **历史报价资产化**：D 盘零散报价 230 文件 → 全文提取（161 份）+ 视觉通道（63 单元）→
   **price_history 表 719 行 / 32 品类**（品名中英/规格/单价/币种/贸易术语/供应商/日期/来源）。
   用途：价格基准锚点（标注"历史报价非实时行情"）、训练样本、格式多样性库。
   - 万达自有模板数据质量最高（型号/材质/FOB/日期全）；brochure 型无价正确跳过。
   - 错名文件（.xls 实为 xlsx）双库互试；临时锁文件（~$ 前缀）跳过。
